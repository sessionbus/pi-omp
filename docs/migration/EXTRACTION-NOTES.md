The frozen inventory maps 105 protected files and 346 original Go tests: 71 Pi/OMP files with 277 tests, two shared packaging surfaces, and 32 shared-support files with 69 tests. The latter resolve from `peer-common` at `eb655f686e4456a4c1121054763318e3d27e89b0`, pinned as `v0.0.0-20260922143100-eb655f686e44`. There is no workspace or local module replacement.

Pi and OMP retain their command wrappers, managed and interactive paths, native extension source, manifests, installers, design and acceptance records. Go changes in protected product files only relocate imports to this module or pinned common support. The package script keeps the two existing extension-copy branches: Pi stages `pi/{extension,native}.mjs` plus `pifamily/extension/bridge.mjs`; OMP stages `omp/extension.mjs` plus the same bridge. The archive installer keeps their Go `--sessionbus-install --plugin-dir` maintenance path. The only canonical URL edits are in the two bootstrap installers. No npm package, Node build step, Node sidecar or peer MCP alias is introduced. Node 24 is needed in CI solely to run the four existing extension test files; the native Pi application already uses Node and OMP uses Bun.

The four extension test files retain 48 static test registrations and pass 50 runtime tests. Two product tests formerly read the closed MCP declaration under the removed OpenCode product tree. A byte-identical copy (SHA256 `bfe5acd1aa93734e66dbe6c79f58a4f2bd7779908103a017cf11c23266e55823`) now lives at `wrappers/pifamily/extension/testdata/sessionbus-tool.json`; only those two test fixture paths changed. It is not packaged or read by either runtime extension.

Release-note links to `docs/designs/pi-omp-0.5.0` remain local and resolve here. The root module, architecture/version checks, CI and archive build are scoped to Pi/OMP. Historical release notes record the original combined release and should not be read as publication of an independent Pi/OMP archive.

Pi and OMP remain **preview** integrations. The original acceptance record distinguishes Pi normal Run, delivery/Forget, interactive replacement and startup/resume from OMP zero-input Worker/interactive and core normal Run. Some fixture outcomes were assessed from retained evidence rather than full fixture passes. Pi admitted interrupt/recovery and OMP staged delivery/Forget/interactive context remain open; arbitrary stdout from an OMP native extension can invalidate its RPC connection. Source preservation does not close those limits.

The `binary-release` and preview-publication workflows remain held during migration. Before enabling Actions, inspect the destination repository's `develop` branch and disable the release workflow or retire that branch; it otherwise publishes on a develop push. No release, permanent UMKA install or fresh native acceptance is part of this source extraction. The original historical evidence remains bound to its tested binaries. Native version/hash is observation provenance, not a compatibility restriction.
