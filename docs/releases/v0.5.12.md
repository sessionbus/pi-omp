# pi-omp v0.5.12

The first release of `pi-peer` and `omp-peer` from this repository. Both remain **preview** integrations.

It requires Sessionbus v0.5.9 or newer (daemon and hub) and pins the Sessionbus Go SDK `v0.5.9` and `@sessionbus/kit` 0.5.9. The version matches core v0.5.12, but this release does not include Go SDK v0.5.12. Native Pi, OMP and Bun are installed separately and are not pinned.

`scripts/install-pi.sh` and `scripts/install-omp.sh` install the latest stable release by default, so they now install v0.5.12. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window.

**Upgrading from v0.5.3 is a flag day.** v0.5.3 pinned SDK v0.5.7, and peers built with SDK v0.5.7 or earlier are incompatible with a v0.5.9 or newer daemon: the lane policy field `idle_message` is removed, and message wake is mandatory. Upgrade the hub, the host daemons and these peers together. Follow the upgrade steps, including the offline lane-row edit, in the [core v0.5.8 release notes](https://github.com/sessionbus/sessionbus/releases/tag/v0.5.8).

## Changes since v0.5.3
- **Own repository.** Pi and OMP are now released from this repository. Their source was extracted unchanged from the combined repository, and shared support comes from the pinned `peer-common` module.
- **Sessionbus Go SDK v0.5.7 → v0.5.9.** See the flag day above.
- **The kit is bundled.** Archives bundle the exact published `@sessionbus/kit` 0.5.9 package, whose registry integrity is checked when the archive is built. Installation needs no Node.js or npm: the Pi extension runs in Pi's own Node process, and the OMP extension in OMP's own Bun process.
- **Native versions are provenance, not a fence.** The exact native package-version and Bun engine-string checks are removed.
  - Still checked: package identity, the exact bin entry and layout, regular-file and executable checks, the runtime shebang, and OMP's physical Bun resolution.
  - Tested provenance: Pi 0.85.1, OMP 18.1.17, Bun 1.4.0.
- **Pi close reports a final protocol error.** Closing a Pi session now waits for the native RPC reader to finish after the child exits, so a final native protocol error is reported instead of lost. Cancelling the close closes and joins an output that is still held open.

## Evidence
No new live/native acceptance was run for this release. The earlier preview results in the [acceptance record](../designs/pi-omp-0.5.0/ACCEPTANCE.md) predate the SDK and packaging changes above.

## Preview limits
- Pi admitted interrupt with healthy recovery, and OMP staged delivery/Forget, remain open work before the preview designation can be removed.
- An OMP native extension that writes arbitrary stdout can invalidate the RPC connection.
